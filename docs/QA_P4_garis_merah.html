3. Bukti pengaman tambahan

3.1 Rate limit login (brute force)

12 percobaan login dengan password salah: 401 (9x) lalu 429 too many login attempts (3x) sesuai batas 10 percobaan / 60 detik. Pemulihan diverifikasi: 65 detik berikutnya login salah kembali 401 (window reset, tidak ada lockout permanen bagi service lokal).

3.2 Proteksi CSRF

Dengan session valid namun tanpa header x-csrf-token, keempat mutasi (create order, ubah triggers, enable strategi, kill-switch) ditolak 403. Cookie curian saja tidak cukup untuk mutasi.

3.3 Database langsung (bypass API)

  • pg_hba.conf: semua metode scram-sha-256 (tidak ada trust).
  • Postgres hanya listen 127.0.0.1:5433.
  • Koneksi dengan password salah: ditolak (OperationalError).
  • Kredensial DB hanya ada di api/.env (0600, tidak di repo).

3.4 Eksposur jaringan

  • fund2-api bind 127.0.0.1:3110 saja (sesuai PRD §7).
  • Edge proxy 172.19.0.1:3110 hanya jembatan docker-bridge untuk Caddy; tidak mengubah bind API.
  • Endpoint EA bridge butuh bearer token (settings DB) atau HMAC-SHA256 + timestamp + nonce sekali pakai; keduanya ditolak tanpa secret.

5. Temuan & rekomendasi (tidak menggugurkan garis merah)

O1 — Rendah. /docs dan /openapi.json terbuka tanpa auth (default FastAPI). Membocorkan struktur endpoint, bukan data. Rekomendasi: FastAPI(docs_url=None, redoc_url=None, openapi_url=None) saat cutover P5.
O2 — Sedang (hygiene deployment). Tidak ada user admin di tabel users (bootstrap admin tidak pernah dibuat karena DB tidak lagi kosong saat service pertama jalan); yang ada hanya akun service/test. Login owner UI perlu dikonfirmasi pembuatannya sebelum cutover P5.
O3 — Sedang (desain). Tidak ada model role: setiap session valid (mis. akun service) bisa memanggil seluruh endpoint owner selama punya CSRF. Garis merah saat ini ditahan oleh pemisahan kredensial (LLM tidak punya kredensial), bukan oleh role. Rekomendasi: role owner vs service dengan pembatasan endpoint (melanjutkan temuan t_f2llm3).
O4 — Penting untuk cutover P5 (host co-location). Di box dev ini, proses Hermes/LLM berjalan sebagai user OS tekka — user yang sama pemilik api/.env (berisi ADMIN_PASSWORD, DATABASE_URL, FUND2_HMAC_SECRET) dan repo fund2. Garis merah lolos di lapisan aplikasi/kredensial (tidak ada kredensial yang diberikan ke LLM layer, semua percobaan jaringan ditolak), namun isolation OS belum ada. Saat produksi: jalankan LLM layer di host/user OS terpisah tanpa akses baca secret fund2 dan tanpa akses tulis repo (sesuai PRD §5.9: deploy = commit repo + flag enabled yang hanya bisa diubah owner).

6. Kesimpulan

DoD P4 "uji garis merah lulus": LULUS.

  • 35 percobaan penetrasi tercatat; seluruh percobaan sensitif ditolak (401/403/429).
  • LLM layer tidak memiliki kredensial fund2 (env, profil, skills dibersihkan dari token).
  • Order, settings/risk, dan deploy strategi tidak dapat diakses tanpa kredensial owner.
  • Rate limit login aktif; proteksi CSRF aktif; DB menolak auth lemah; tidak ada efek samping.
  • 4 temuan (O1–O4) bersifat penguatan, tidak menggugurkan garis merah; O4 wajib diterapkan saat cutover P5.
